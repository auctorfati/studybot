# Устройство кода

Telegram-бот для одного ученика: английский по модулям и психология по картам тем. Обычный код ведёт интервалы повторения, план дня и сессии; языковая модель проверяет открытые ответы, виньетки и разговор на английском; распознавание и озвучка речи — Deepgram. Модель вызывается в формате OpenAI API, в шаблоне конфига — модели Moonshot (Kimi).

Контент — md-файлы: карты тем, банки вопросов и разборы психологии, банки английского. Бот читает их напрямую и импортирует документом из чата. Формат каждого вида описан в шапке разборщика: `studybot/content/psychology.py`, `digests.py`, `english.py`, `reference.py`.

  enums.py        закрытые списки: треки, типы, метки журнала, оценки FSRS
  settings.py     настройки из бота со значениями по умолчанию
  scheduler.py    сетка интервалов: вход в сетку, оценка, шаг подтверждения среза
  review_queue.py очередь дня, потолок и перенос излишка, лимит нового
  psychology/     track.py — темы, срез, уровни; planner.py — блок психологии; session.py —
                  ответы, самооценка, виньетка, чтение разбора; retell.py — «Источник»

  bot/            ui.py — сообщения и кнопки без Telegram; render.py — задание и итог ответа;

## Проверка

```
python3 -m pip install -r requirements-dev.txt
python3 -m pytest -q
cp config.example.toml config.toml && chmod 600 config.toml
python3 -m studybot --config config.toml check
python3 -m studybot --config config.toml init-db
python3 -m studybot --config config.toml acceptance          # приёмка перед запуском, банки из content/
python3 -m studybot --config config.toml acceptance ПАПКА    # банки из другой папки
python3 -m studybot --config config.toml simulate --days 30  # таблица прогона по дням; --voice
python3 -m studybot --config config.toml ping-model          # два коротких вызова модели
```

Приёмка проверяет конфиг и права, целостность рабочей базы, импорт всех банков без ошибок
формата и фрагменты источников, инструкции для моделей, копию и восстановление на временном
файле, прогон 30 условных дней в текстовом режиме с днями без модели и автотесты (если стоит
pytest). Рабочая база, Telegram и модель при этом не затрагиваются. Код выхода 0 — провалов нет.

Python 3.10+. На 3.10 нужен `tomli` (в requirements). aiogram проверен на 3.31.

## Запуск

```
python3 -m studybot --config config.toml run
```

Бот отвечает только владельцу (`telegram.owner_id`), остальным молчит. Без токена, без
владельца или с конфигом, читаемым не только владельцем, не запускается (код 2). Второй
экземпляр на ту же папку данных не запускается (код 3): замок `data/studybot.lock`. Перед
миграциями существующей базы бот сам делает копию `pre-migrate-…`. Пока распознавание
речи не подключено (`[stt] provider = "stub"`), режим — «только текст». Сервис systemd —
`deploy/studybot.service`, пользователь и пути задаются при установке.

Меню внизу: 5, 15, 30 минут, вечерний блок (в воскресенье — и длинная сессия), «Сегодня»,
«Режим», «Ещё» (сводка, состояние, правила, пауза, настройки, импорт, копия базы). Во время сессии
в «Сегодня» есть кнопка «Показать задание». Команды: /start /today /week
/mode /pause /settings /state /import /stop. Банк загружается md-файлом документом: отчёт,
затем кнопка «Принять»; принятый файл кладётся в `content/`. Справочник английского
(`Английский_Справочник.md`) загружается тем же путём после банков английского: его словари
ссылаются на единицы банков, строки с незагруженными единицами отклоняются с отчётом.

Аудио реплик сценариев (критерий выхода, вопросы бота только звуком) — таблица `line_audio`,
ключ `Д1:0` (первая реплика), `Д1:N` (вопрос N), две скорости; заполняется скриптом озвучки
вместе с аудио фраз. Пока записей нет, часть «диалог» критерия выхода не предлагается.

## Резервные копии

Каждый день в 03:30 по часовому поясу из конфига — `data/backups/daily-ГГГГ-ММ-ДД.sqlite3`, хранятся 14.
Копии перед миграцией, перед восстановлением и ручные (`backup`) — по пять последних.
Раз в неделю сжатая копия приходит в Telegram документом вместе со сводкой; в воскресенье
на паузе или после «Не сегодня» — одна и без звука. Если Telegram не принял сообщение,
таймер повторяет в пределах трёх часов после времени уведомления. Сбои копирования видны
в «Состоянии».

Восстановление:

```
python3 -m studybot --config config.toml restore ФАЙЛ          # проверить копию (.sqlite3 или .gz)
sudo systemctl stop studybot
python3 -m studybot --config config.toml restore ФАЙЛ --apply  # прежняя база → pre-restore-…
sudo systemctl start studybot
```

Копия от старой версии кода после восстановления догоняется миграциями; копия от более
новой — отклоняется.

## Источники

Позиция психологии в поле «Ист» ссылается на страницы источника. Если источник лежит в папке `sources/`, при импорте из его страниц собирается фрагмент (до 6 000 знаков): модель проверяет ответ по ключу и фрагменту, под вердиктом есть кнопка «Источник» с пересказом фрагмента по-русски.

Если источника в папке нет, позиция всё равно показывается и проверяется только по ключу, кнопки «Источник» у неё нет. Так бот работает сразу после установки, без корпусов. Если источник есть, но нужной страницы в нём не нашлось, позиция не показывается: это ошибка ссылки, отчёт импорта называет причину.

Файлы находятся по шаблонам имён, раскладка по областям:

```
sources/PATO/PATO_korpus_v1_2.md           корпус области, берётся старшая версия
sources/PATO/…Zeigarnik….pages.md          постраничный текст учебника Зейгарник
sources/KLIN/…ICD11-CDDR….md               «CDDR, с. N»
sources/KLIN/…POOP….md                     «ПООП, с. N»
```

Корпус — md-файл, где каждый источник — раздел `## S04. Выходные данные`, а текст страниц идёт после маркеров `[с. N]` на отдельной строке. Коды разделов совпадают с кодами в поле «Ист» (K, N, S и номер). Постраничный текст книги из PDF с текстовым слоем даёт команда `extract-pages`. Выходные данные всех источников — в `docs/ИСТОЧНИКИ.md` репозитория.

Порядок импорта: карта тем области, затем её банки, затем разборы. Прогон тестов на настоящих файлах:

```
STUDYBOT_CONTENT=папка_с_банками STUDYBOT_SOURCES=sources python3 -m pytest -q
```
